# 多产品网站：产品露出、目录组织与增长方式

研究日期：2026-10-17。针对 Jamin 提出的「产品出现多次，看起来奇怪」进行第二轮研究。Sindre 是大量产品如何排版的参考，不是指定视觉模板。本轮沿用已选定的系统无衬线、主站配色与图标光学校正。

## 结论

当前最合适的是：**短作者开场 → 唯一应用目录 → 简短关于 → 页尾**。

首页每个产品只保留一个完整条目。条目回答「叫什么、做什么、能在哪用、是否可获取」，详情页再回答「具体怎么工作」。取消顶部六图标条；上一轮已取消的两款精选不恢复。没有明确关联理由的详情页推荐也删除。

这不是要求全站产品名称只出现一次。导航身份、支持入口、长页末尾的获取按钮，各自承担任务；重复营销卡片和重复口号则不应凭空占用页面。

## 1. 参考站：观察与适用范围

以下四站均通过官方页面文本与实际浏览器观察；没有进行转化、性能或完整无障碍评测。外站内容会变化，下面记录的是本次访问结果。

| 参考 | 本次实际观察 | 对本项目的启发 | 不直接采用的部分 |
| --- | --- | --- | --- |
| [Sindre Sorhus / Apps](https://sindresorhus.com/apps) | 页面标示 61 款应用。DOM 中 61 个含图标的主内容产品链接，对应 61 个不同地址；Featured 4 款和 More Apps 57 款没有重复。1280px 下为两列横向卡片，信息结构一致，提供多个分类入口。 | 产品可以分区，但同一次目录浏览中不必重列；图标、用途、平台是可比较的稳定字段。 | 61 款应用的分类维度、统计数字和渐变品牌视觉，不是六款应用必须具备的设计。 |
| [Many Tricks](https://manytricks.com/) | 短介绍后开始应用列表，以图标、名字与简短用途为核心；新闻和页尾导航另有位置。 | 多产品首页不一定需要截图舞台；直接说明用途能迅速进入浏览。 | 不沿用其具体字体、长列表密度或页尾完整产品索引。 |
| [Apptorium / Apps](https://www.apptorium.com/apps) | 统一纵向卡片，图标、名称、用途及下载/详情操作；桌面三列。品牌开场占据较多首屏空间。其首页另有发布与新闻内容。 | 每款应用使用同一种信息格式，即使素材情况不同，也能形成完整目录。 | 不同时增加品牌首页、应用目录与新闻体系；不在我们的每张卡片上堆两种操作。 |
| [Rogue Amoeba](https://rogueamoeba.com/) | 七款主要产品用图标与一句用途组织，另有发布提示、获取与支持入口；不同位置存在服务目的的重复链接。 | 数量接近，说明较少产品也适合直接目录；区分「发现产品」和「已有用户找支持」。 | 不照搬强背景、大图标墙、每项多个商业操作和庞大页尾。 |

因此，问题不在于找一个「比 Sindre 更好的站」：Sindre 对目录规模最有参考价值，Many Tricks 对短开场有价值，Apptorium 对统一条目有价值。应组合适合当前内容的原则，而不是换一套外站皮肤。

## 2. 当前问题在哪里

| 位置 | 之前的职责与问题 | 本轮处理 |
| --- | --- | --- |
| 首页六个图标 | 与下方六个目录条目指向同样的页面，缺少用途信息；桌面和手机都增加一次重复浏览。 | 删除图标条及紧邻的「探索应用」跳转；目录直接接在短介绍后。 |
| Aperlo / FIRE 双精选 | 最初按现有素材完整度选择，并无产品优先级依据；截图与小组件也不是同一种构图。 | 保持上一轮的删除。今后有明确发布目标时重新判断，而不是为了填版面恢复。 |
| 目录标题和标语 | 开场已有品牌句，再写一组宣传型区块标题，延迟进入产品。 | 用简短的 Apps / 应用，加平台筛选和数量。 |
| 详情页固定两款推荐 | 从配置中排除自己后取前两款，并非真正的用途关联；Aperlo / Rouse 反复得到额外露出。 | 删除这组卡片。全站 Apps 导航仍可返回目录。 |
| 无截图的产品首屏 | 导航已有身份，正文又有名字和用途，右侧大图标舞台再次重复名字与说明；手机上独占一大段。 | Rouse / PriceBird / Hushtrail 改为紧凑开场；72px 图标与身份组合，不再另设图标海报。 |
| 支持汇总的应用入口 | 访问者已经有应用，要进入对应帮助；与首页发现产品是不同任务。 | 保留，复用目录组件，链接明确进入支持页。 |
| 产品内导航与文档标题 | 导航说明当前在哪个产品；正文标题说明当前文档是什么。 | 保留上下文，不以机械去重破坏定位。 |

## 3. 脑爆：三个结构方向

### A. 单一应用目录——本轮选择

短作者介绍 → 两列目录（窄屏一列）→ 关于作者。

- 每款应用一处。图标、用途、平台、必要状态按同一顺序出现。
- 没有截图的应用不会被降为次要产品，截图精美的应用也不会自然变成「精选」。
- 整个条目进入产品详情；获取方式在详情页说明，FIRE 的「准备发布」仍明确展示。
- 保留轻量平台过滤。默认全部可见，不增加搜索、排序、价格、标签云和平台分区重复清单。
- 新产品主要添加配置和内容，目录构图不随每款应用重新设计。

代价：不专门强化某一款产品，也不在首页详细演示产品操作。这与当前缺少主推优先级、希望浏览完整产品的目标相符。

### B. 按任务分组——产品更丰富时再判断

例如「工作与整理」「日常生活」，各组展示属于它的应用。

优点是先从需求出发；缺点是当前每组只有少量应用，分类标题比节省的扫描成本更多，Rouse、Aperlo 等也跨场景。不要让同一款应用为适应分类而重复出现在多个区块。未来可把多个标签用于筛选，仍只渲染一份结果集。

### C. 主打产品 + 其余目录——明确发布活动时才启用

一款新发布应用作为主视觉，其余应用接在后面。主打应用从余下集合中排除。

优点是能讲清一次发布；代价是素材成本、优先级维护和首页更新负担。需要明确「为什么是它、持续多久、结束后恢复什么」，当前没有这个前提。设计板中只展示结构草图，不代表指定 Aperlo 为主推。

设计预览 `/design/` 展示三种结构草图，完整实现只保留 A，避免维护三份网站。

## 4. 目录的具体设计

- **桌面两列**：为一句用途与平台留足宽度；最大内容宽 1200px，不为了容纳更多产品缩小文字。680px 及以下一列。
- **图标主体 72px**：继续使用共用 AppIcon；Aperlo / Trailglass 仍通过配置补偿透明留白。新增产品先校准可见主体，不能只比较 PNG 宽度。
- **轻量分隔线**：延续现有视觉语言，不增加每产品一块彩色背景或不同高度的大截图。
- **信息顺序**：名字 → 直接说明用途 → 平台 → 必要发布状态。标题与用途可自然换行，不截断本地化文本。
- **唯一点击目标**：整条进入详情，无嵌套按钮。箭头是可见的进入提示；焦点样式、触摸目标沿用共用规范。
- **稳定顺序**：当前保留六款配置顺序，不声称按热度、推荐或下载量排序。FIRE 仍标准备发布，不能因状态影响筛选而隐藏其平台。
- **平台筛选**：过滤当前清单，不复制出一份 Mac、一份 iPhone 清单。跨平台应用只出现一次。无脚本时显示全部条目。
- **个人身份**：顶部一句作者介绍，底部保留 WWDC 经历与联系渠道；不添加虚构受众数字、奖项或评价。

## 5. 增长到更多产品时

以下是设计判断的检查点，不是经研究证明的固定数量阈值。

| 规模与信号 | 应对方式 |
| --- | --- |
| 当前六款，到约十余款，仍可快速扫描 | 延续同一目录；保持短用途、稳定顺序、平台筛选。 |
| 页面明显变长，访客常按名字找应用 | 再加入名称/用途搜索；与筛选叠加，保留无脚本入口与空结果提示。 |
| 每种用途已拥有数款产品，分类有稳定意义 | 添加用途过滤或独立 Apps 页；优先看真实条目能否清楚归类，不先造空分类。 |
| 有明确的阶段性主推产品 | 采用 C；从其余目录去重，定义发布提示结束时间，不能长期叫所有产品「最新」。 |
| 停止维护的产品增加 | 提供单独的历史应用入口；现有支持/隐私 URL 继续有效，不用首页宣传区保持曝光。 |

当前不添加虚构应用来撑大目录，不引入 CMS、分页或客户端框架。正式迁移继续沿用仓库的静态构建方式：产品配置、内容、共享组件与生成 HTML 分离。

## 6. 复用边界

- `AppIcon` 负责视觉尺寸与留白校正；不让每个页面手写缩放补丁。
- `ProductCard` 负责名称、用途、平台、状态和入口；首页与支持入口共享布局，改变目标路由。
- `Catalog` 只接收一份产品集合。若今后添加主推区，应在构建期拆分为不相交集合。
- `ProductHero` 根据是否有真实界面，选择截图、小组件或紧凑身份开场；无素材不生成看似真实的 UI。
- 推荐模块不再是详情页默认组成。未来要加入，必须有明确相关性字段和解释，而非配置顺序。
- 所有更改限制在 `_design`，iCube 与线上内容保持原状。

## 7. 验证边界

静态校验仍检查原有 87 个产品路由、事实段落、服务/发布 URL 与图片引用。浏览器检查覆盖实际目录次数、平台过滤、宽窄布局、浅深色与紧凑产品页。具体结果记录于 `../VALIDATION.md`。

尚未获得访客数据、转化对比或真实用户可用性测试。因此本轮结论是基于内容、页面任务和实际排版的设计选择，不能声称提高了转化率。
