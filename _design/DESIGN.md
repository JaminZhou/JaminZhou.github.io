# JaminZhou 网站视觉设计提案

日期：2026-10-17；已根据浏览器标注与第二轮多产品目录研究精修。状态：视觉设计已实施到本地正式构建流程，研究与原型过程见下文。范围：个人首页、六款当前产品及其全部现有语言与内容页面；**iCube 排除**。线上尚未发布；本地实现状态见第14节。

## 1. 设计判断

建议将网站调整为「独立开发者的产品目录」，用一致的图标与用途建立第一印象，用结构稳定的目录承接不断增长的项目，再用产品页和文档完成解释与支持。

当前需要调整的核心是信息层级。每个项目都占用相同的大舞台，会使主页随着产品增加而变长；产品页、语言页各自保留不同的布局，又会逐渐削弱家族关系。仅仅换颜色或字体不足以解决这些问题。

主方向是自然的浅色底、深墨色文字、系统无衬线字体、低饱和产品色，以及真实图标与应用界面。整体气质应是专注、清楚、有人的存在感。六个产品无需被包装成同一款应用，也无需增加企业式宣传、虚构评价或下载数字。

**设计成功的判断**：首次访问者能迅速理解作者与产品；找产品的人能扫描用途和平台；已安装用户能进入对应语言的支持；新增产品主要新增内容而不是复制整页 CSS。

这是一套基于当前内容的设计判断，尚无访客分析、转化实验或用户访谈证明它提升了转化率。

实际浏览器观察与仅网页文本研究的区别见研究文件。没有测量参考站的转化率、性能或无障碍合规。

脑爆比较了三种构图：

| 方向 | 适用性 | 取舍 |
| --- | --- | --- |
| **清晰的应用目录：主方案** | 六款不同类型应用，并会继续增加 | 短开场、尺寸一致的应用图标、完整目录，真实截图在产品页展开 |
| 按任务分组 | 每个稳定用途都有数款产品 | 当前条目少且跨场景，先保留平台过滤；今后按实际内容评估 |
| 主打 + 其余目录 | 有明确发布与推广目标 | 主打从其余目录排除，需要选择理由、结束时间与真实素材；当前暂不采用 |

设计页展示三个构图方向，完整页面只制作主方案。没有把三个缩略构图宣称为三套完成的网站。

## 3. 信息架构与页面职责

现有部署有 102 个 HTML：88 个内容页、12 个旧 CalcBird 跳转页、2 个 iCube 隐私页。设计原型覆盖原来的 1 个首页与 87 个产品页，另外展示中文首页概念、支持汇总、404、设计总览、组件页、响应式检查台，共 94 页。

| 类型 | 用户问题 | 主要内容与设计 |
| --- | --- | --- |
| 首页 | 有哪些产品，哪个适合我？ | 作者定位 → 完整目录 → 简短关于 |
| 产品页 | 能做什么，如何获取？ | 一句话用途、真实视觉、主操作、平台/版本/状态、任务与能力、相关帮助 |
| 支持汇总 | 我应该去哪里求助？ | 六个明确入口，随后提供通用联系渠道 |
| 产品支持 | 如何解决我的问题？ | 简介、帮助主题、FAQ、反馈、隐私；不加入营销型巨幅首屏 |
| 隐私 | 具体处理什么数据？ | 正文优先、更新日期、可扫描标题与目录，不改写法律内容 |
| 更新记录 | 这个版本改了什么？ | 左侧版本、右侧说明；窄屏单列；目录统一使用版本号 |
| Rouse 合盖指南 | 有哪些条件，如何安装/恢复？ | 长文阅读区、步骤、代码、实际警告、章节锚点 |
| 404 | 下一步去哪里？ | 明确错误状态，返回目录与支持的两个入口 |

产品矩阵：Rouse 9 语言 × 5 类页面；PriceBird、Aperlo、FIRE 各 4 × 3；Hushtrail、Trailglass 各英文 × 3。具体 URL 与内容来源在生成的 `preview/design/routes.json`。

原 URL 是公共契约。正式迁移不改变已有目录、语言代码、隐私链接或下载入口。12 个旧跳转与 2 个 iCube 页面继续按原方式提供。`/codex-ui-kit/` 是独立项目站点，本轮不迁移其网站，首页不主动宣传。

## 4. 首页完整构图

1. **导航**：头像与 JaminZhou 是返回主页入口；Apps、About、Support 三个任务；邮件图标有可读名称。移动端折叠菜单保留相同入口。
2. **开场**：左侧简短标题，右侧一句作者介绍；900px及以下自然堆叠。删除图标条与额外跳转按钮，下一段直接进入应用目录，每款产品只出现一次。
3. **不设双精选**：初版因为素材齐全选择 Aperlo 与 FIRE，但缺乏明确的产品优先级，且应用截图与小组件的构图不同。根据实际预览反馈取消这组陈列，所有应用以同一目录结构呈现；截图与小组件在各自产品页承担解释任务。未来只有明确的发布或推广目的时才重新设计专题入口。
4. **全部应用**：每项固定图标、名称、一句话用途、平台和必要状态。桌面与中屏两列，680px及以下一列。目录以分隔线组织，避免再生成一组大型舞台卡片。
5. **平台筛选**：仅 All / Mac / iPhone & iPad 三项，默认显示全部。研究倾向六款时甚至不需要筛选；本稿保留轻量筛选是为了快速排除不支持的设备，不引入搜索、价格、标签或排序工具栏。无 JavaScript 时仍可看到全部应用。
6. **关于**：作者照片、简短理念、`Apple WWDC 2014 Student Scholarship Winner`、邮件与 GitHub。保持个人身份，不扩展为冗长履历。
7. **维护范围**：Codex UI Kit 暂缓维护，当前主页不再主动展示开发者工具宣传区。原生产站及独立项目本身不在这次预览修改范围。
8. **页尾**：常用链接、版权、主题选择。桌面版权左、外观选择器右，垂直居中；760px及以下分行左对齐。选择器桌面高32px，触控设备44px；页尾上下内边距24px。预览已移除“Design preview”链接，直接呈现生产版对齐；设计方案保留在独立的 `/design/` 页面。

内容增长时优先延续相同目录。页面明显变长、访客按名字寻找时再评估搜索；稳定类别中各有数款应用时再评估分组或独立 Apps 页。不以固定数量自动触发复杂界面。若今后主推一款应用，必须从其余集合去重。

## 5. 字体与排版

**推荐整体改为系统无衬线**。旧站 Cormorant Garamond + Lora 的双衬线更像编辑出版物；新站包含多产品、版本、平台、说明和多语言，需要更稳定的扫描层级。无需为视觉更新新增字体网络请求或许可证依赖。

| 角色 | 字号 | 字重/行高 | 规则 |
| --- | --- | --- | --- |
| 首页展示标题 | 约 36–52px | 650 / 1.1 | 两行优先，不裁切；中文不继承英文负字距 |
| 产品主标题 | 38–60px | 650 / 1.08 | 英文最多约 18ch，手机可增宽；不限制行数 |
| 页面与文档 H1 | 32–45px | 650 / 1.2 | 保留内容结构；不用装饰小字替代标题 |
| 区块标题 | 28–40px | 650 / 1.2 | 文档 H2 收至 24px |
| 导语 | 18px，手机 17px | 400 / 1.75 | 只用于简介，不把整篇正文放大 |
| 正文 | 16px | 400 / 1.65–1.8 | 中文/日文段落 1.85；阅读宽度最多 700px |
| 导航/按钮 | 15px | 500–600 | 按钮最小高度 44–46px，文本可折行 |
| 辅助信息 | 13px | 400–500 | 不用低对比浅灰承载重要条件 |
| 代码 | 14px | 400 / 1.8 | 系统等宽；代码块局部横向滚动 |

拉丁字形：`ui-sans-serif, -apple-system, BlinkMacSystemFont, Segoe UI, sans-serif`；中文 SC/TC 分别回退 PingFang 与微软字体；日文 Hiragino Sans / Yu Gothic；韩文 Apple SD Gothic Neo / Malgun Gothic。不同系统具体字形会变化，不能把 macOS 截图当作 Windows 验收。

英文字距仅对大标题轻微收紧；中文、日文、韩文主标题为 -0.015em、1.2 行高，正文不额外加负字距。版本数字使用 tabular-nums。品牌名不强制翻译：Aperlo 在简/繁中文显示“映窗”，PriceBird 显示“算鸟/算鳥”。

没有采用自定义字体不代表永久排除。如果后续需要更鲜明的品牌字形，可仅在首页展示标题试用一款有完整许可的字体；正文、文档、UI 继续复用系统字体。需要重新验证中文、日文、德文长度和加载回退。

## 6. 颜色、空间与细节

| 语义 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| Canvas | #F8F9F5 | #1B211D | 整体画布，避免纯白/纯黑的极端对比 |
| Surface | #FFFFFF | #242C26 | 菜单、少量组件面板 |
| Ink | #222B25 | #EEF2E9 | 正文、标题、主按钮 |
| Muted | #59655C | #B8C4B8 | 次级说明，仍须满足正文对比 |
| Quiet | #647067 | #AAB8AB | 元信息，不用作禁用内容的唯一线索 |
| Brand | #345B43 | #B8D1AD | 主站强调色 |
| Focus | #376BCA | #A5C5FF | 3px 焦点外框，offset 4px |
| Border | #D7DDD4 | #435047 | 装饰性分隔线；输入控件使用更强边界 |

产品色为 Aperlo 青绿、Rouse 橄榄、PriceBird 陶土、Trailglass 蓝、Hushtrail 金棕、FIRE 暖橙。它们用于舞台底色、链接和少量标识，正文保持统一。深色单独指定颜色，不靠全页反相或降低图片透明度。

空间基本刻度：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128px。按钮圆角 12、普通卡片 20、展示舞台 28。仅舞台、菜单和截图需要阴影；目录和文档主要用空白和细线分区。页面最大宽 1200px，左右边距 20–64px，长文阅读区 700px。

链接：普通正文保留下划线，导航通过位置与 hover 区分；跨站链接可用 ↗，站内前进使用 →，页内下移使用 ↓。应用目录使用站内 →，避免被理解为必然开新标签。无必要不强制新标签。

动效为 160ms 的颜色/轻微位移，最多 1–4px；不做自动轮播、滚动视差或持续漂浮。尊重 reduced-motion。按钮按下归位、禁用有状态，不能只靠颜色传达选择或状态。

### 图标与选择器精修

Aperlo 的图案主体为206/256px，Trailglass为412/512px，二者均自带透明边缘；其余四款基本铺满画布。共用AppIcon组件为前两者应用1.242718倍光学校正，不修改PNG本身，也不把原有圆角再裁一遍。规则同时用于目录、产品导航、紧凑产品开场、支持文档与组件页。

目录与紧凑产品开场72px、产品导航36px、文档标识48px。图标条和大图标海报已删除。标题、间距和点击区域跟随角色，而不是所有位置使用同一个像素值。

语言菜单与外观选择共用16px SVG向下箭头；语言菜单展开时旋转，替代字体字符箭头。外观保留原生select的键盘与选择面板，隐藏平台自带的小箭头，通过同一SVG统一闭合状态。语言入口使用18px地球图标替代双圈字符。

## 7. 产品页的统一与个性

共用顺序：产品导航 → 用途与获取 → 媒体 → 平台/版本/发布状态 → 功能或任务 → 深入说明/截图 → 发布详情 → 页尾。固定的两款“其他应用”推荐已移除；暂无真实相关性依据。

三种媒体模式是可复用的布局，不是每个产品一套站点：

| 模式 | 当前产品 | 规则 |
| --- | --- | --- |
| screenshot | Aperlo、Trailglass | 保留截图原比例，可打开原图；整图先于细节；图注说明示例内容 |
| widgets | FIRE | 一张中尺寸 + 两张小尺寸，配置路径和语言；不伪造个人财务数据 |
| icon | Rouse、PriceBird、Hushtrail | 72px图标与产品身份形成紧凑开场，省去独立海报，让功能正文提前；不拼造软件界面 |

### 每款产品的内容与素材方向

| 产品 | 第一认知 | 建议补充/重拍的任务截图 | 特殊边界 |
| --- | --- | --- | --- |
| Aperlo / 映窗 | 不导入图库，直接浏览图片 | 一张干净真实窗口 + 图库 + 图片细节/全屏 | 当前素材是带宣传标题的商店截图；网页已保留原比例，正式网页资产应减少重复标题 |
| Rouse | 长任务期间保持唤醒 | 定时会话 + 显示器睡眠独立控制 + 菜单栏 | Helper 是单独安装的组件；合盖限制与恢复说明不能藏掉 |
| PriceBird / 算鸟 | 比较真实单价 | 规格不同的双商品比较 + 优惠输入结果 + iPad布局 | 示例币种/价格注明示例；iPad兼容运行不能标成原生Mac版 |
| Trailglass | 理解本地 AI 会话记录 | 会话库 + 对话详情 + 工具活动 | 截图只用模拟会话，不能泄露真实密钥、私有项目或用户记录 |
| Hushtrail | 看清范围后再决定清理 | 已选应用 + 残留审核 + 不可清理原因 | 历史删除可能不可恢复、无应用备份等说明保留在正文；直链旁保留发行说明 |
| FIRE | 偶尔记录，用小组件看见目标 | 现有小组件可用，后续补最小记录过程 | 保留准备发布，不制造可下载状态，不把投资回报当承诺 |

图片交付建议：保留源 PNG，另生成 480/960/1440px 响应式 WebP/AVIF；sRGB，明确宽高，首图 eager、下方 lazy。产品截图不要为了卡片统一而裁掉系统要求、状态、内容或操作按钮。小图难以辨认时给局部细节图或原图入口，而不是放大假的文字。

FIRE 图标在本地浏览器首次无法解码；预览采用原文件的重新编码版本，已确认显示。技术原因未进一步归因，原生产文件未改。素材来源与生成方式见 [assets/README.md](assets/README.md)。

## 8. 组件与交互契约

| 组件 | 必需输入 | 必须支持的状态与行为 |
| --- | --- | --- |
| SiteHeader | 主站入口、链接、当前语言 | 桌面/手机；菜单展开、Escape关闭、焦点返回 |
| ProductNav | 产品、当前surface、实际语言集合 | 当前页标记；语言切换停留同一类页面 |
| AppIcon | 原始图标、用途尺寸、光学校正系数 | 保留原图；同一角色的可见图案大小一致；不叠加第二层裁切 |
| ProductCard | 名称、用途、平台、状态、URL、图标 | 整项链接、hover、focus；文案变长时自然增长 |
| ProductHero | 标题、导语、获取状态、媒体模式 | App Store / direct / preparing，三种明确分支 |
| ActionGroup | 主/次链接、可读标签 | 一组仅一个视觉主操作；窄屏换行；不渲染假按钮 |
| LocaleMenu | 当前语言、可用同页翻译 | 原语言自称、当前状态、键盘操作、滚动菜单 |
| ThemeSelect | system / light / dark | 持久保存失败时仍可工作；原生select，跨页保持；页尾桌面32px，粗指针44px |
| DocumentTOC | 本页真实标题与唯一锚点 | 桌面sticky、手机details；不遮盖跳转目标 |
| FAQ | 原问题与答案 | 原生details；不用JS也能展开；每题独立 |
| Callout | 说明类型、标题、正文 | 用文字说明限制；warning只用于实际操作风险 |
| ReleaseEntry | 版本、标题、内容、可选日期 | 桌面双列、窄屏单列；目录标签统一版本号 |
| Screenshot | src、宽高、alt、图注、原图 | 原比例、延迟加载、失败仍保留说明 |

静态站没有数据请求型业务流程，无需为展示添加 skeleton 或 loading spinner。目录的空结果有明确文字；无JS时不显示无效筛选控件。实际网络加载失败仍应由浏览器可理解的图片替代文字/外部目标处理。

## 9. 响应式与多语言

| 范围 | 布局 |
| --- | --- |
| >1050px | 首页双列开场、两列目录；有截图的产品左右构图，无截图的产品紧凑开场；文档侧目录 |
| 761–1050px | 目录两列；900px及以下首页开场单列；不缩小文字来保住列数 |
| 481–760px | 首屏与产品媒体上下排；移动导航；文档目录折叠；680px以下目录单列 |
| ≤480px | 目录单列、版本记录单列、按钮换行；边距20px |

重点尺寸 320、390、768、1280px。检查台是同源真实 iframe，不是图片缩放；iframe 内实际宽度受边框影响约少 2px，会记录实测值。它能测试CSS布局，不能替代真机Safari、触摸/缩放、系统字体和屏幕阅读器验证。

语言内容保持原URL与完整正文。9种Rouse语言共用同一个组件结构，禁止再用英文专属data属性和翻译页专属class分别维护两套设计。不同语言可使用不同文字长度与段落数量，不追求高度相等。

原型新增加的中文首页是概念文案，其他语言的主站链接明确返回英文首页；全站支持汇总目前是英文。产品的语言菜单只显示同一surface已存在的语言。正式落地应将所有新UI字串加入现有locale资源，并显示明确的英文目标提示。产品卡跨语言无对应介绍时标记 English，不默默假装已翻译。

## 10. 可访问性与性能目标

采用 WCAG 2.2 AA 作为正式实施目标，参考 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)；这不是现有原型已获得合规认证的声明。

- 正文对比至少 4.5:1，大号文字3:1；控件边界和焦点按适用条件至少3:1。装饰性分隔线不按正文标准判断。
- 本设计触控目标以44px为内部目标。WCAG 2.2 AA的最小目标条款是24 CSS px及相关间距/例外，不能混称所有元素强制44px。
- 每页一个H1、main landmark、skip link、明确lang；图标链接有名称；装饰图使用空alt。
- 筛选使用按钮与aria-pressed，数量通过polite live region反馈；当前页用aria-current。
- 320px不整页横向滚动；代码块/宽表可以局部滚动；测试200%文字缩放、400%缩放与键盘顺序后再声明满足reflow。
- 检查减少动态、系统高对比、无JavaScript、图片失败、屏幕阅读器和系统主题变化。
- 不引入SPA框架或大型运行时。关键HTML静态输出，主题、筛选、菜单仅作增强。
- 正式性能预算：共享CSS压缩后≤30KB，JS压缩后≤8KB；首屏图片合计尽量≤400KB。首图必须有宽高，后续图片懒加载，首屏字体0请求。
- Core Web Vitals目标LCP≤2.5s、INP≤200ms、CLS≤0.1，来源 [web.dev](https://web.dev/articles/vitals)。当前未获得线上真实用户指标或节流Lighthouse测量。

原型为了保留真实截图证据，复制了原始PNG，**尚未满足生产图片预算**。不得将设计验收与性能上线验收混为一谈。

## 11. 复用架构与源真相

保留静态 GitHub Pages 与构建时模板；无需迁移 React/Next、CMS 或服务端。

五层边界：

1. **tokens**：字体、颜色、间距、断点、圆角、动效和主题。页面不重新定义自己的正文色。
2. **components**：导航、卡片、操作、语言、截图、FAQ、目录、版本条目。组件不知道某产品版本号。
3. **templates**：homepage、product、support/document、changelog。首页与长文密度不同，但依赖相同基础组件。
4. **product metadata**：标识、品牌名、平台、分发方式、媒体模式、产品色、图标光学尺寸。优先扩展现有 `_site-src` metadata，而非再造永久平行数据源。
5. **localized content**：每语言的标题、描述、功能、截图、alt、支持与隐私正文。翻译只决定内容，不决定DOM骨架。

原型的 `products.json` 是设计阶段的仓库快照；不是新增永久版本源。`build.py` 导入现有HTML并归一布局，以检验全量内容适配。它包含兼容旧结构的adapter，**不等同于生产模板已迁移**。正式落地应把归一结果实现为现有Node构建器的共用模板，然后逐步移除adapter和inline style。

推荐数据契约：

```text
Product
  id, names[locale], category, platforms[], minimumOS
  release { version, channel, storeURL?, downloadURL?, releaseURL?, status }
  theme { lightAccent, lightSurface, darkAccent, darkSurface }
  media { mode, hero[locale], gallery[locale][], alt[locale] }
  icon { scale, radius }
  locales[], surfaces[]

PageContent
  title, introduction, sections[], actions?, updatedAt?
  Section = feature | screenshot | prose | faq | callout | release
```

新增应用流程：建metadata → 提供英文本与真实素材 → 选择已有媒体模板 → 接入实际语言与surface → 构建 → 路由/链接/内容检查 → 桌面与窄屏可视验收。新增第七款不应改导航CSS、卡片布局或复制产品页骨架。

只抽象有真实第二个用途的模式。不把Hushtrail清理限制、Rouse Helper操作、FIRE目标展示强行压成同一个字段列表。特殊内容使用共用Prose/Callout/Screenshot区块；出现稳定重复后才新增组件。

## 12. 内容与发布约束

- 版本、最低系统、免费/付费、发行链接先对照现有源真相，发布前再核验实际商店/发行状态。当前原型不是商店实时状态审计。
- 隐私、退款、系统权限、Helper恢复与Hushtrail不可逆删除说明保留原文，视觉设计不授权改政策。
- 不新增虚构评分、下载量、测试设备覆盖或“所有系统兼容”承诺。
- 原始图片仅来自本仓库，未上传到第三方设计服务；参考站只用于原则研究，不复制资产。
- 生产SEO保留canonical、hreflang、语言路由、标题、Open Graph、sitemap与robots。原型统一noindex并禁止抓取，正式构建必须移除预览标识。
- 页面URL变更如确实必要，先列映射和301/静态跳转策略；本方案没有要求变更现有URL。
- iCube文件、独立样式和sitemap记录应以基线hash验证不变，不能因全局CSS重构被动受影响。

## 13. 实施顺序与验收

1. **基础与组件**：将tokens和共用组件放入现有构建体系，先迁移一页产品、一页文档和两种语言，确认结构。
2. **全量产品页**：按矩阵迁移87页，版本、下载、权限和隐私逐项read-back；接入真实素材。
3. **首页与支持汇总**：切换统一目录数据、确认产品排序和中文首页是否正式上线。
4. **发布前检查**：全链接、fragment、资产、canonical/hreflang、SEO、键盘、不同字体系统、真机、图片优化、性能。
5. **部署后read-back**：从真实URL检查首页、各产品、旧跳转、隐私和iCube；线上状态与本地构建分开报告。

每一阶段保持可单独回退的提交；不同时修改产品功能、隐私政策和视觉模板。原站保留直至新模板通过验收。
